# dsmem：可配置记忆曲线的 DeepSeek 记忆插件 · 设计说明

> 一句话：把"记住一切"换成"按重要性分级 + 按曲线遗忘 + 自己学会怎么评级 + 不靠翻聊天记录维持人格"。

本目录是一份**可运行**的设计，不只是文档。`python demo.py` 会跑完三天完整生命周期：
初始化 → 对话入缓冲 → 夜间固化 → 召回 → 评级自校准 → 人格演化 → 日记/日志 → 空闲行为。

---

## 1. 目标与非目标

| 目标 | 实现方式 |
|---|---|
| 用户能在最开始一次性设定"记忆手感" | 4 个倾向问题 → 推导出全部参数（用户不写公式）；空间不设上限 |
| 记忆分三档，逐档衰减 | L0 缓冲 / L1 情节 / L2 核心锚点 + 独立日志层 |
| 评级不是人填的 | 模型在初始化时自己生成 v1 评级体系，之后按真实召回行为自校准 |
| 人格稳定但会被长期改变 | 对话持续产出"人格证据"，按 强度×情境×持续时间 积分；单次改不动，按周/按季设预算上限 |
| 不依赖聊天记录维持自我 | 人格不从对话里"检索"，只从 `self_model` 读；原文默认永不注入 |
| 每天写日记，再提炼日志 | 日记（叙事）+ 日志（结构化索引），日志是召回主入口 |
| 空闲时能做别的事 | 插件调度器：能力声明 + token 预算 + 冷却，产出只进日记，不打扰用户 |
| 省空间、少读 | SQLite 单文件 + zlib + 标签索引（无向量库）+ 预算化召回 |

非目标：不做多用户云端同步、不做向量检索（在 10 万条以内，标签 + 实体 + 摘要的重合度足够，且成本低一个数量级）。

## 2. 结构总览

```
                 ┌──────────────────────────────┐
   每轮对话 ───▶ │ L0 缓冲层 buffer             │ 原始轮次，TTL 36h
                 │ 全量落盘，什么都不判断        │ 不建索引，不注入
                 └──────────────┬───────────────┘
                                │ 夜间固化（评级一次）
              ┌─────────────────┼──────────────────┐
       salience < t_discard   t_discard≤s<t_core   s ≥ t_core
              │                 │                  │
          直接删除          ┌───▼─────────┐   ┌────▼──────────┐
        （只留统计）        │ L1 情节层    │   │ L2 核心锚点    │
                            │ 六要素骨架   │◀──┤ 完整对话(zlib) │
                            │ + 一句提要   │   │ 只写不读       │
                            └───┬─────────┘   └────┬──────────┘
                                │ full→skeleton→cold→删除
                                ▼
                        ┌───────────────┐
                        │ 日志层 logs    │  日记写完后的提炼，召回主入口
                        └───────────────┘
   人格 self_model ◀── 证据流（每段对话都算）── 慢通道积分，按月/按年生效
```

存储只有 5 张核心表：`buffer` / `fragments` / `anchors` / `logs` / `journal`，外加 `self_model`、`rubric`（评级体系版本）、`recall_receipts`（召回凭证）、`plugins`。

## 3. 分组（空间）：一个分组一个库文件

分组是这套系统里最硬的一条隔离线。用户或管理员在界面里手动选择，选完这个分组就只碰它自己的库。

### 3.1 为什么是"一空间一文件"

给每张表加 `space_id` 是常规做法，但漏写一个 `WHERE` 就会串记忆。改成物理隔离后，串记忆在结构上不可能发生，还顺带解决三件事：整组备份、整组迁走、整组删掉。

```
<root>/spaces.json            分组清单 + 当前选择 + 会话绑定
<root>/spaces/<id>.db         该分组的全部记忆（buffer/fragments/anchors/logs/journal/murmurs/self_model）
<root>/exports/<id>/          按月 Markdown 归档
<root>/backups/*.zip          备份
<root>/trash/                 删除的分组挪到这里，不 rm
```

分组 id 保留中英文（`技术群-c2ad`），一眼能认出来；后缀哈希防重名。

### 3.2 新分组继承什么

| 项 | 是否继承 | 理由 |
|---|---|---|
| 评级体系 rubric | 继承 | 评级是"我"的能力，不该每个群重新学 |
| 记忆曲线配置 | 继承 | 同一个用户的手感偏好 |
| 人格 self_model | 可选（默认继承） | 同一个角色，但亲密度会各自长各自的 |
| 记忆内容 | **不继承** | 这就是隔离本身 |

### 3.3 手动选择与会话绑定

- 界面顶部的下拉框 = 当前分组，切换即切库；
- `POST /api/bind {chat_id, space}` 把某个群/会话钉死到分组，`resolve(chat_id)` 供机器人接入时路由；
- 没有绑定就落到"当前选择"，不会乱猜。

### 3.4 群聊与个人用户：一个分组里两套记忆池

分组是**容器**，里面可以同时放群聊和个人用户。记忆归谁，由"这个人在不在这个群里"决定：

```
渠道是群聊           →  池 = g:<群>        （群和群内所有人共用）
用户在该群里         →  池 = g:<群>        （和群共通）
用户不在任何群       →  池 = u:<用户>      （只有自己的）
用户被标记为"私密"   →  池 = u:<用户>      （即使在群里也隔离）
```

`identity.resolve(channel)` 给出 `{write, read, shared, group}`，写和读用同一个池；
`scope` 列落在 `buffer / fragments / anchors / logs / journal / murmurs / chapters` 七张表上，
召回时 `WHERE scope IN (...)`。

**人格不跟着分池。** 一个分组只有一份 `self_model`，所有渠道的对话都往同一张
`self_evidence` 里投证据 —— 所以"群里更熟"会体现在私聊里，"私聊里更放松"也会带进群。
这正是"人格互通且互相影响"的实现方式：池子分开，人是同一个。

界面上的选择提醒（`identity.advise`）：同时勾了群聊和用户时，
不在该群里的用户会被标出来 —— "只会得到独立记忆，建议改选群内成员，或先把他加入该群"。
成员卡片里，勾进群的用户是绿色"共享"，没勾的是橙色"独立"，一眼能看出来。

代价要说清楚：入群共享意味着**在群里能想起你私聊说过的话**。如果不想这样，
把这个用户标成"私密"，他就始终用自己的池。
## 4. 第一步：人为 setting（只给倾向，不给参数）

`dsmem/settings.py` 问 4 个问题，其余全部推导（**不问空间，因为没有上限**）：

| 问题 | 含义 | 影响 |
|---|---|---|
| forget | 多快忘掉琐事 | 丢弃阈值、半衰期增益、删除天数 |
| detail | 细节要到什么程度 | 核心阈值、召回预算、L2 保留比例 |
| journal | 日记风格（散文/要点/意识流/极简） | 日记模板 |
| personality_strength | 人格多强 | 漂移上限、核心层权重 |

推导示例（`build_config`）：

```python
t_discard          = 0.24 + 0.34 * forget
t_core             = 0.62 + 0.20 * detail
half_life_gain_h   = 120  + 260  * (1 - forget)
recall_budget      = 320  + 600  * detail      # token
drift_cap_per_week = 1    + 4    * personality_strength
```

内置 4 个预设：`工具人`（快忘、低人格）、`长期伴侣`（慢忘、重人格）、`工作助理`（重承诺细节）、`创作缪斯`（重情绪与日记）。四者都不限容量。

```bash
python -m dsmem.settings --db memory.db --preset 长期伴侣
python -m dsmem.settings --db memory.db --interactive    # 逐项问答
```

## 5. 遗忘曲线

幂律式的指数衰减，但半衰期由"重要度"决定，并带间隔效应：

```
初始稳定性  S0 = (base + gain * salience^1.6) * (core ? 2.4 : 1)
可回忆度    R(t) = 0.5 ^ (Δt / S)
召回强化    S' = min(Smax, S * (1 + 1.4 * (1 - R)))     ← R 越低被想起，涨得越多
```

含义：
- 重要度 0.61 的事，S≈191h，30 天后 R=0.07（该忘了）；
- 重要度 0.80 的事，S≈634h，30 天后 R=0.46（还清楚）。
- 每一次被真正用到，半衰期就变长 —— 这就是"用进废退"。
- 长期没人碰的记忆，`decay_stability()` 会缓慢侵蚀，避免"僵尸记忆"永久占位。

调 `forget` 就是整体平移 `gain`；用户不需要理解公式。

## 6. 评级体系：模型自己长出来

### 5.1 初始分级（v1）由模型生成
用户只给倾向。`RUBRIC_PROMPT` 交给 DeepSeek 生成 7 个维度权重 + 每维判据：

| 维度 | 判据 |
|---|---|
| self_ref 自我指涉 | 是否在说"我"的偏好/身份/边界 |
| affect 情绪强度 | 情绪词密度与强度 |
| novelty 信息新颖 | 相对已知实体表的增量 |
| commitment 承诺时限 | 有没有时间点、待办、承诺 |
| goal 目标相关 | 与当前活跃目标的重合度 |
| recurrence 反复出现 | 是否是老话题的延续 |
| explicit 明确要求 | 用户是否说"记住/以后都/别忘" |

评分 = 加权和，再叠加**保底规则**（保底也是评级体系自己的一条策略，同样随版本演进）：

| 条件 | 保底 | 理由 |
|---|---|---|
| explicit + affect + self_ref 同时成立 | 0.80 | 身份级偏好 + 明确要求 → 直接判核心 |
| affect≥0.8 且 self_ref≥0.6 | 0.72 | 身份级偏好 |
| commitment≥0.6 | 0.58 | 含时限的待办，至少要进 L1 |
| explicit 单独成立 | 0.50 | 说了要记，但语义信号单薄 |

每条记忆入库时都会带一行 `reason`（例：`自我指涉1.00、情绪强度1.00；身份级偏好 + 明确要求，判为核心，保底 0.80`）。
**这行理由是可审计的关键**：出问题时能回答"它凭什么被升级"。

### 5.2 自校准（v2, v3, ...）
每次 `calibrate()`：
1. 取所有带维度向量的记忆；
2. 分成"被召回过的"和"全体"两组，算各维均值；
3. 均值之差 × 学习率 0.18 加回权重，归一化；
4. 版本 +1，写 `rubric.notes`。

直觉：**被真实用到的记忆 = 评级预测正确的记忆**。如果命中的记忆普遍"承诺/时限"得分高，说明这一维被低估了，权重就该上调。实测一跳（demo）：

```
v1 -> v2（样本 3 条/命中 2；承诺/时限+0.22、目标相关-0.20）
```

生产环境建议：累计 ≥20 条样本再校准，每周一次，单次学习率 ≤0.2，并且保留最近 20 个版本以便回滚。
用户永远不需要手改权重 —— 他只能通过"用不用这条记忆"来间接投票。

## 7. 分层与清理

| 层 | 内容 | 生命周期 | 读频率 |
|---|---|---|---|
| L0 buffer | 原始轮次 | TTL 36h，或固化后立即删 | 只在固化时读一次 |
| L1 fragments | 六要素（who/what/when/where/why/how）+ ≤70 字提要 | full → skeleton（提要截断）→ cold → 删除 | 高 |
| L2 anchors | 当时完整对话（zlib，实测压到 62%） | 核心常驻，闲置 180 天转 cold | 极低（只有 detail 召回才解压） |
| logs | 日记后提炼的 1–3 条重点，带 kind 与权重 | 长期 | 最高 |
| journal | 当天第一人称日记 | 长期（每篇 150–250B） | 低（睡前复盘用） |

`age_fragments()` 每晚按 R 值跑状态机：`R<0.25 → skeleton`，`R<0.08 且超期 → 删除`。
`garbage_collect()` 还会检查总字节数，超预算时按 `salience × R` 从低到高淘汰 —— 空间是硬约束，不是建议。

## 8. 连续性：删得掉细节，删不掉时间

遗忘曲线会真的删东西。删完之后如果那段时间变成空白，人设就会"失忆感"很重。所以删除前多一步：

```
fragments 过期 → continuity.absorb() 折进月度章节 → 才 DELETE
```

`chapters` 表按 `period`（`2026-10`）唯一，保存一段 600 字以内的概览、涉及标签、事件计数、被折入的条数。

三条保证：
1. 只要某个月有过活动，就一定有该月章节（`ensure_month`）；
2. 章节永不自动删除，长度封顶 600 字，不会反向膨胀；
3. 召回时如果细节层没有命中，自动回落到最近章节 —— 回答"那阵子在忙什么"够用。

`coverage()` 会给出跨度和缺口。缺口是诚实的：那几个月确实没聊过，不编造。
## 9. 日记 → 重点 → 日志

顺序刻意如此（先写日记，再提炼）：

1. **日记**：一天结束时用第一人称写，风格由 setting 决定。它是"自我叙事"，不是索引。
2. **提炼**：从当天情节里抽 1–3 条，分类为 `commitment / preference / insight / relation / lesson / event`，带权重和回指 `fragment_id`。
3. **日志**：召回时的第一入口。一条日志 ≈ 30 字，而原文一段 ≈ 200 字。

好处：问"我讨厌什么"时，只需要读一条日志就能答，不必解压任何原文（实测 162 tok 完成一次召回）。

## 10. 碎碎念：人格给默认值，用户可以覆盖

碎碎念是"没人看也要说"的那部分。默认频率和长度由当前人格等级算：

```
每天条数 ≈ 0.6 + 2.2×亲密度 + 1.0×幽默      （0.6 – 3.8）
单条长度 ≈ 16 + 40×幽默 + 18×亲密度 − 22×直接度  （10 – 80 字，短促口吻再压到 18 以内）
口吻    = argmax(直接度−0.55, 幽默−0.58, 亲密度−0.62)，否则"平静"
```

实测三种人格：

| 分组 | 人格 | 每天 | 每条 | 口吻 | 样例 |
|---|---|---|---|---|---|
| 技术群 | 幽默 .80 / 亲密 .75 / 直接 .40 | 3.05 条 | 52 字 | 俏皮 | 半夜的对话总是比白天的真一点。 |
| 家人群 | 幽默 .30 / 亲密 .90 / 直接 .40 | 2.88 条 | 35 字 | 亲近 | 深夜说的话，我会多留一会儿。 |
| 项目A | 幽默 .20 / 亲密 .30 / 直接 .85 | 1.46 条 | 10 字 | 短促 | 睡吧。 |

**内容由记忆状态决定**，四种主题按优先级取：

1. 刚清理过记忆 → "遗忘"（"今天顺手清掉几件小事，只记得个大概"）
2. 有日志 → "记忆"（把最近一条重点塞进句子）
3. 深夜 → "深夜"
4. 否则 → "空闲"

### 10.1 用户可调：每天几条、每条多长

界面「日记 · 碎碎念」页有一张**碎碎念调节**卡片，两个输入框：

| 设置 | 字段 | 范围 | 0 的含义 |
|---|---|---|---|
| 每天条数 | `murmur_per_day` | 0 – 30，可带 0.5 | 跟随人格自动（默认） |
| 单条字数上限 | `murmur_length` | 0 – 200 | 跟随人格自动（默认） |

规则：

- **条数是目标数量**：设 5 就每天生成 5 条，`daily_cap = ceil(5)`；手动模式下硬上限跟着走，不再固定 8。
- **字数是上限**：模板本身短就短，不会为了凑字数复读；只有设置了更大的上限、且预算够时，才补一两句**和当前话题相关**的延展（`TOPIC_TAIL`）。所以 `60` 得到 20–45 字，`200` 也不会变成几百字的注水。
- **口吻不跟着改**：幽默/亲密/直接度决定口吻，用户只调数量与体积。想改口吻，得让对话慢慢改变人格。
- 值按**分组**保存（写进该库的 `meta.config`），不同群可以不一样；输入 0 点保存即恢复自动。

实测（技术群，人格幽默 .80 / 亲密 .75）：

```
自动：每天 3.05 条 · 每条约 52 字 · 俏皮
手动 5 条 / 60 字上限：每天 5 条（硬上限 5）· 单条最多 60 字 · 预计 0.9 KB/天
  (41字)「半夜的对话总是比白天的真一点。这个点的话，我存得久一点。夜里想的事，白天不一定认。」
```

自动模式下每天最多 8 条，由 `builtin.murmur` 在空闲调度里触发（冷却 90 分钟），也可以界面手动生成。真实部署时把 `MURMUR_PROMPT` 交给模型写，离线时用模板兜底。

一条边界：**碎碎念不进系统提示**。它是私下的独白，如果把独白也塞回上下文，模型会把自己的猜测当成事实复述。它只落库、只进归档，用户主动翻才看得到。
## 11. 人格：会被聊天记录改变的慢通道

人格**不是**封闭设定，也**不是**一次对话就能改的开关。它是一个积分器：
每段对话按 **强度 × 情境 × 持续时间** 折算成"人格证据"，证据自己也会衰减，
只有反复出现、并且撑够跨度的证据，才能把等级推动一点点。

### 8.1 一条证据怎么算

`rating.trait_signals()` 只读用户侧发言，输出 `(trait, direction, intensity, context)`：

| 因素 | 取值 | 含义 |
|---|---|---|
| 强度 intensity | 命中 1 次 0.4；2 次 0.7；≥3 次 1.0；明确要求 ≥0.9 | 说得越密集越算数 |
| 情境 context | 基础 0.45；深夜(22–02) +0.18；长谈(≥300 字) +0.15；情绪浓度 +0.18；一句话带过 −0.15 | **环境**决定这句話的分量 |
| 明确 explicit | 关键词与「以后都/别再/一直」**同句**才算 | 防止"以后别这样"误伤无关特质 |

### 8.2 证据如何变成改变

```
单条权重  w = intensity × context × 0.5^(Δ天 / 半衰期)
压力      p = tanh( Σ±w / 2 )              ∈ (-1, +1)
步长      step = step_max × p × (1-惯性)^1.5 × min(1.5, 0.5 + 跨度/120)
```

三重闸门，任何一条不过就不动：

| 闸门 | 演化层（humor / closeness） | 核心层（directness 等） |
|---|---|---|
| 证据天数 | ≥3 个不同日子 | ≥8 个不同日子 |
| 时间跨度 | ≥7 天 | ≥45 天 |
| 压力 | ≥0.12 | ≥0.5 |
| 明确要求 | 可走快车道：单次即给 0.05，方向按用户说的来 | **不适用**，核心层只认长期证据 |

再加两道预算（这是"改变要花时间"的硬保障）：

- `weekly_drift_budget ≈ 0.044`：一周最多挪这么多等级，防突发情绪；
- `evolving_window_budget = 0.25` / `core_window_budget = 0.10`：**90 天**内最多挪这么多。
  演化层一个季度最多变 0.25，核心层最多变 0.10 —— 想更快也没额度了。

### 8.3 实测（demo 第 ⑫ 段，60 天）

| 场景 | 结果 |
|---|---|
| 第 1 天一次性吐槽"你太冷了" | 只留一条强度 0.4 的证据，压力 +0.05，**不动**（天数跨度都不够） |
| 第 2 天改成"以后别这么闷，多说点有意思的" | 明确要求走快车道，0.35 → 0.39，一次到位但只给 0.05 |
| 连续 60 天深夜长谈（强度 0.7、情境 0.63） | 幽默 0.35 → 0.605，亲密度 0.50 → 0.755，**都卡在季度上限 0.255 上，第 45 天后就停住** |
| 第 40 天单独一次"今天别开玩笑了" | S 只从 +6.63 掉到 +6.42（约 0.8 天的积累），**方向不变** |
| 每 3 天说一次"说重点，别绕弯子"（核心层） | 直到第 50 天（跨度满 45 天）才首次生效，60 天总共只挪 **0.018** |

这就是"会被改变，但需要时间"的量化版本：**演化层按月计，核心层按年计。**

### 8.4 其余约定
- 每次改动都写 `self_deltas`：`before/after/reason/pressure/evidence_n/span_days/version`，完整可回溯。
- 用户在对话里**直接要求改核心设定**（如换称呼），仍走 `propose_delta` → 挂起等批准，不自动改。
- 证据本身 200 天清理一次；143 条证据约 4.4 KB（含全部人格表）。
- 注入 prompt 的自我描述固定 ~115 tok：**当前状态**进 prompt，**证据流水**不进。人格是"积分结果"，不是"检索原文"——这才是"不过度依赖聊天记录"的真正含义。

## 12. 召回协议：预算化、分层、默认不读原文

```
recall(query, budget):
  A. 自我            ~110 tok   永远包含
  B. 日志（近 14 天，按重合度×权重取 ≤4 条）
  C. 情节骨架（标签/实体/提要重合 × 重要度 × R，取 ≤4 条）
  D. 原话            仅当 query 命中"原话/当时怎么说/逐字"时，解压 1 个锚点的一段
  超过预算立刻截断（truncated=True）
```

三个硬约束：
1. **默认永不读 transcript**。原话是写多读少的冷数据。
2. **召回即强化**：命中的片段 `S *= 1 + 1.4(1-R)`，把"用进废退"闭环。
3. **召回凭证** `recall_receipts` 记录每次查询用了多少 token、碰了哪几层、命中哪些 id —— 既能审计"是否过度读取"，也能反哺校准。

实测（3 天数据，680 tok 预算）：

| 查询 | 用掉 | 层级 | 读原话 |
|---|---|---|---|
| 我讨厌什么？ | 162 | self+logs+fragments | 否 |
| 杭州出差要带什么 | 166 | self+logs+fragments | 否 |
| 我当时原话怎么说的？ | 262 | +transcript | 是（仅此一次） |

## 13. 空闲行为与插件接口

宿主在"无用户消息 ≥10 分钟"时调用 `run_idle()`，按 `priority` 取任务，受 `cooldown_s` 与 `token_budget` 约束，单次最多 2–3 个。

**插件清单 `manifest.json`：**

```json
{
  "name": "example-reflection",
  "api_version": 1,
  "version": "1.0.0",
  "capabilities": ["reflect"],
  "tier_access": ["L1"],
  "token_budget": 300,
  "priority": 5,
  "cooldown_s": 1800,
  "storage_quota": 65536
}
```

**钩子 `hook.py`：**

```python
def run(ctx):            # ctx = {store, cfg, now, budget}
    ...
    return {"note": "一句反思", "tokens": 90}
```

### 13.1 行为总线：插件干了什么，日记和碎碎念知道

插件不只是"说一句话"，它可以把**做过的事**报上来，宿主写进 `activities` 表：

```python
def run(ctx):
    return {"note": "…", "tokens": 90,
            "activities": [{"kind": "reflect",
                            "title": "重读了「向量库选型」，想到它当时的分量",
                            "detail": "…", "weight": 0.6}]}
```

`kind` 决定日记里的措辞（`prune` 整理记忆 / `review` 翻旧事 / `reflect` 自己想 /
`note` 干杂活），`weight` 决定同一天里谁排前面，`title` 是可以直接读的一句结果。

这份数据有两个消费者：

| 消费者 | 怎么用 |
|---|---|
| 日记 `write_journal` | 有情节就写在后面，没情节就单独成一篇（"只有插件在干活的一天"也有日记）；语气跟人格走：直接度高就只列事实，幽默高就加一句自嘲 |
| 碎碎念 `murmurs` | 话题优先级：**遗忘 > 插件 > 记忆 > 深夜 > 空闲**。6 小时内的插件行为会被优先说；短促口吻装不下长标题，就换短说法（"翻了翻旧事。"） |

两条纪律：
1. **产出不算行为**。`builtin.murmur` 返回 `activities: []`，否则"我刚说了两句话"会变成日记素材，越滚越荒唐。
2. 插件可以显式传 `activities=[]` 表示这次什么都不算；不传才用 `note` 兜底。

实测（demo 第 ⑨-b 段）：

```
行为总线：[review] 把「我们决定把这个记忆插件做成三层：…」又看了一遍   ← builtin.reviewer
日记补写：… 回头翻了翻旧事，把「…」又看了一遍。
碎碎念：  [短促/插件] 翻了翻旧事。
```

兼容性与安全边界：
- `api_version` 大于宿主支持版本 → 静默跳过，不炸主流程。
- 权限按 `tier_access` 白名单发放；**默认不给 transcript 权限**。
- 插件产出一律写入日志/日记草稿，不直接进对话（避免"AI 自说自话"）。
- 插件异常被捕获成一行 `idle_log`，不影响主链路。
- 有 `storage_quota`，超额的插件会被拒绝注册。

内置任务两个：`builtin.gardener`（空间巡检，20 tok）、`builtin.reviewer`（挑最接近遗忘阈值的记忆主动回顾，30 tok）。

## 14. 归档格式：按天分节，按月分文件

日记和碎碎念分开存两条流，但都按日期索引。落到磁盘时：

```
exports/<分组>/journal/2026-10.md     # 日记：每天一个 ## 小节
exports/<分组>/murmurs/2026-10.md     # 碎碎念：每天一个 ## 小节，条目带时间
```

为什么不是"一天一个文件"：一年 730 个小文件，inode 和目录遍历的开销远大于内容本身。按月分文件、内部按天分节，天粒度照样可检索，文件数压到 12/年。

实测一个月：日记 97B、碎碎念 164B（三条），合计不到 300 字节。DB 仍是主存储，Markdown 是给人看和防 DB 损坏的副本。
## 15. 备份与恢复：三种版本，去重，每天一份

同一个库，导出成三样东西（日记那一样存在**另一个目录**）：

| | 完整记忆 `full` | 当前记忆 `current` |
|---|---|---|
| 内容 | 一个字都不删 | 只留此刻还记得的 |
| 原始轮次 buffer | 保留 | 清 |
| 冷片段 / 冷锚点 | 保留 | 删 |
| 人格证据流水 `self_evidence` | 保留 | 清 |
| 人格历史版本 `self_deltas` | 保留 | 清 |
| 召回审计 / 空闲流水 / 丢弃统计 | 保留 | 清 |
| 人格当前值 `self_model` | 保留 | 保留 |
| 日志 / 日记 / 碎碎念 / 月记 | 保留 | 保留 |
| 用途 | 回到某一天 | 搬走此刻的人格与记忆 |
| 体积（实测 20 条冷数据 + 30 条证据） | 33.9 KB | 31.7 KB |

第三类 `diary` 是纯文本：`diary/<分组>/journal/*.md` + `murmurs/*.md`，默认打包到
`diary-backups/`（与记忆备份分开），实测 3.1 KB。

### 15.1 去重：三层

1. **zip 里不再放 Markdown 归档**。以前每个备份都夹一份 `exports/*.md`，那是数据库内容的
   逐字副本 —— 纯重复。现在文本只存在于 `diary/` 和日记备份里，记忆备份只装库。
2. **内容指纹**。建备份前先算 `payload_hash`：记忆类是对每个库做行级哈希（不是文件哈希，
   页布局会变），日记类是对所有 md 文件哈希。和上一次同类备份相同就直接返回
   `deduped: true`，不产生新文件。
3. **文本归档只追加**。同一天的日记被重写时，归档不覆盖旧段落，而是补一节「修订 20:31」，
   所以不会因为反复改写堆出多份全文。

每日任务因此可能一份都不生成：没新内容就没有新文件，这是预期行为。

### 15.2 日记与碎碎念：分开存，不能删

```
<root>/diary/<分组>/journal/2026-10.md     只追加
<root>/diary/<分组>/murmurs/2026-10.md     只追加
<root>/diary-backups/dsmem-diary-*.zip     单独的备份
```

- 遗忘曲线 **不碰** `journal` / `murmurs` 两张表；`garbage_collect` 只删 `fragments`。
- `backup.prune()` 默认跳过 `diary` 类型，要删得显式传 `kind="diary"`。
- 恢复日记时**只增不删**：目标文件不存在才写；已存在且内容不同，另存为
  `xxx.restored-<时间>.md`，原文不动。

当前版是**在快照上做删减 + VACUUM**，原库一个字节都不动。删减行数会写进 manifest，恢复前能看到到底丢了什么。

每日自动：`dsmem.daily` 一天各做一份，三种触发方式任选 —— 界面开着时后台线程每 10 分钟检查一次；
`python -m dsmem.daily` 挂计划任务（不依赖界面）；界面上的"立即执行今日备份"按钮。
同一天重复调用只会备份一次。

```
manifest.json                 # 版本、类型、时间、分组清单、每个文件的 sha256
spaces.json                   # 分组清单与绑定
spaces/<id>.db                # 各组数据库快照（当前版已削过）
exports/<id>/journal/*.md     # 文字归档
```

四个细节决定它靠不靠谱：

1. **用 SQLite backup API 取快照**，不是直接拷文件 —— 先 `wal_checkpoint(TRUNCATE)` 把 WAL 并回主库，再备份，避免拿到半写状态；
2. **快照切成单文件模式**，备份里不需要 `-wal` 也能独立打开；
3. **恢复前先校验 sha256**，然后**自动给当前状态再做一次备份**（`pre-restore`），走错了能回去；
4. **恢复时清掉旧的 `-wal`/`-shm`**，否则残留 WAL 回放会把删除又带回来 —— 这个坑实际踩过。

界面里可以浏览任意目录作为备份位置（服务端目录浏览器，不是浏览器沙箱），也可以只校验不恢复。

备份目录里只动 `dsmem-full-*.zip` / `dsmem-current-*.zip` 这两种文件；清理旧备份是显式操作（`backup.prune`），不会自动删。

> 注意：完整版是"当天数据库的完整副本"，不是"历史上所有版本的集合"。如果某条记忆已经被遗忘曲线删掉了，它不会在今天的新完整版里复活 —— 要保住它，靠保留那几天的 zip。已被删内容仍会在月度章节里留下压缩痕迹（见第 8 节）。
## 16. 空间账本（实测）

| 项 | 数值 |
|---|---|
| 3 天 / 15 轮对话后总计 | **1.9 KB** |
| L1 | 1.2 KB |
| L2（1 个锚点） | 0.4 KB（564B → 351B，压缩 62%） |
| 自我 + 元数据 | 0.3 KB |
| 被丢弃的低价值会话 | 2 个（省下约 0.1 KB，且不占后续任何 token） |
| 每轮固定注入 | 384 tok（上限 700） |

线性外推：每天 40 轮、约 1 个 L2 + 3 个 L1 的情况下，一年约 3–6 MB。

**没有容量上限，配置里也没有这个字段**：`CurveConfig` 不设 `max_bytes`，`garbage_collect` 里
没有"超预算淘汰"的分支。删记忆只剩遗忘曲线一个原因，不受体积约束。

> 升级说明：老版本把 `max_bytes` 存在 `meta.config` 里（4 MB）。只把默认值改成 0 不够——
> 一加载旧配置又会读回来，界面还显示 "上限 4096 KB"。所以 `Store._migrate()` 会把
> `max_bytes` / `space_mb` 从旧配置里直接抹掉，字段不存在了，就不存在被复活的可能。

省空间的三处设计：不存向量（用标签/实体重合）、原文 zlib、低价值会话直接删（连摘要都不留）。

## 17. 接入 DeepSeek（三个时点）

```
用户消息 ──▶ recall() ──▶ 拼进 system prompt ──▶ DeepSeek chat ──▶ 回复
                                                          └─▶ add_turn(user/assistant) → L0
每天 23:30 ──▶ nightly() 固化 → write_journal() → make_logs() → 每周日 calibrate()
无消息 10min ──▶ run_idle()
```

模型调用适配（只用在三处：评级理由、六要素抽取、日记撰写；都用 `response_format=json_object`、`temperature=0`）：

```python
def rate_session(client, turns, rubric):
    r = client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "system", "content": RUBRIC_PROMPT.format(**needs)},
                  {"role": "user", "content": json.dumps(turns, ensure_ascii=False)}],
        response_format={"type": "json_object"}, temperature=0)
    return json.loads(r.choices[0].message.content)
```

离线时 `rating.py` 里的确定性启发式会顶上（demo 即走这条路），因此整个系统没有模型也能跑通、能做回归测试。

## 18. 风险与对策

| 风险 | 对策 |
|---|---|
| 评级漂移，把重要的忘了 | 关键是"保底规则 + 召回即强化"：用过一次就很难掉出去；`pinned` 可长期钉住 |
| 错误记忆被固化 | 每条记忆带 `reason` 与来源锚点，可追溯；日记里允许写"我当时可能记错了" |
| 模型用记忆编造细节 | prompt 明确"只用摘要作答，不确定就说不知道"；细节必须走 detail 召回 |
| 人格被一次对话带跑 | 三重闸门（天数/跨度/压力）+ 每周 0.044、每季 0.25 的双层预算 + 完整 delta 历史 |
| 人格该变却不变（过僵） | 明确要求走快车道（单次即给 0.05）；核心层满 45 天跨度即自动生效，不必人工批准 |
| 空间失控 | 硬水位淘汰 + 插件配额 + 原文压缩 |
| 召回过度读取 | token 预算 + 凭证审计 + 默认不读原文 |
| 插件互相污染 | 命名空间、能力白名单、只写日志不写对话、异常隔离 |
| 分组之间串记忆 | 物理隔离（一空间一库），不是靠 WHERE 约束 |
| 群内私聊内容被群看到 | 归属规则默认可共享，但提供"私密"标记强制隔离；界面明确标示当前池 |
| 同一场对话被记成两份 | 选人时提示"优先从群内成员里选"，未入群用户直接标橙 |
| 备份看着成功、实际读不回来 | sha256 清单 + 恢复前校验 + 恢复前自动再备份 + 清残留 WAL |
| 备份目录被误删文件 | 只操作 `dsmem-backup-*.zip`，清理需显式确认 |
