## 2. 短简介（README 顶部 / 分享用，3 句）

dsmem 给对话模型一套会衰退的记忆：重要的事沉进长期层，琐事按曲线消失，被用到的记忆会活得更久。人格不靠每次重读聊天记录，而是由长期对话的强度、情境与持续时间积分而成 —— 改变得慢，但确实会变。整套逻辑只用 Python 标准库，一个分组一个 SQLite 文件，离线可跑。

## 3. 完整简介（发布页 / 项目介绍）

大多数所谓的 AI 记忆，是把历史整段塞回上下文，或者丢进向量库等下次相似检索。前者昂贵且噪声大，后者只能"找到"，不会"淡忘"。

dsmem 换了个方向：把记忆当成一个有生命的系统。

- **会忘**：每段对话先落在 36 小时缓冲层，夜间固化。值得留的压成"六要素 + 一句提要"，重要到一定程度才保留原话，其余直接丢弃，连摘要都不留。
- **忘得有依据**：每条记忆有自己的半衰期，越重要衰减越慢；被召回一次，稳定性就被拉长。没有容量上限，删除只由遗忘曲线决定，删之前先折进月度章节，时间线不断档。
- **重要度不是人定的**：初始化时由模型生成 7 维权重，之后用真实召回行为反向校准。每条记忆都留一行理由，可以审计它凭什么升级或降级。
- **人格是慢通道**：一段对话只产出一条证据，按"强度 × 情境 × 持续时间"积分。演化层按月变，核心层按年变，有周/季预算，单次情绪改不动它。
- **记忆按分组隔离**：一个分组一个 SQLite 文件。群聊与个人用户按"在不在这个群里"决定共享还是独立；人格始终只有一份，所有渠道互相影响。
- **日记与碎碎念**：按日期归档，只追加、不删除；碎碎念的条数与字数可以自己调，也能从其他插件的行为里取材。
- **能带走**：完整记忆 / 当前记忆 / 日记文本三种备份，内容指纹去重，每日自动各备一份。

没有向量库，没有第三方依赖，没有后台服务。一个分组一个 `.db`，`python -m dsmem.webui` 就能看到它在想什么、忘了什么、为什么忘。

**适合**：长期陪伴型角色、需要跨会话连续性的助手、想研究记忆衰减与人格漂移的人。
**不适合**：想找向量检索库的、想直接调模型 API 的 —— 这里只有记忆层，不代管推理。
